# VM architecture / Arquitectura de la VM

## English

### Execution model
- Operand **stack** (data)
- **Locals** array (indexed slots)
- **Call stack** (return IP + frame info)
- **Bytecode** array (`optc` after optimize)
- **String pool** (interned strings)
- Optional file/array pools for higher ops

### Instruction cycle
1. Fetch opcode at `ip`
2. If trace: log op, args, source line
3. Dispatch: pop/push stack, read/write locals, branch, call, etc.
4. Gas/`max_steps` guard against infinite loops

### Entry
Programs start at bytecode offset 0. Use `jmp main` before `include` so library code is not executed as the entry point.

## Español

### Modelo de ejecución
- **Pila** de operandos (datos)
- Array de **locales** (slots indexados)
- **Pila de llamadas** (IP de retorno + frame)
- Array de **bytecode** (`optc` tras optimizar)
- **Pool de strings** (internados)
- Pools de archivos/arrays para ops avanzadas

### Ciclo de instrucción
1. Leer opcode en `ip`
2. Si trace: log op, args, línea fuente
3. Despacho: pila, locales, saltos, call, etc.
4. Límite `max_steps` contra bucles infinitos

### Entrada
El programa empieza en el offset 0. Usa `jmp main` antes de `include` para no ejecutar la lib como entrada.

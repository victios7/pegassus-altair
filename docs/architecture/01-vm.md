# VM architecture (long) / Arquitectura de la VM (larga)

## English

### Big picture
Pegassus executes a linear array of bytecode instructions. Each instruction is an opcode optionally followed by immediate operands (slot numbers, jump targets, string ids).

There are three important storage regions:

1. **Operand stack** — where almost all calculations happen.
2. **Locals** — random-access cells addressed by integer indices.
3. **Call stack** — return addresses for `call` / `ret`.

Additionally the runtime owns a **string pool**, optional file handles, and optional arrays.

### Why a stack machine?
Stack machines make it easy for frontends to emit code without a register allocator. A expression like `(a+b)*c` becomes:

```text
load 0        ; a
load 1        ; b
add
load 2        ; c
mul
```

### Instruction pointer
`ip` advances after each instruction. Jumps assign `ip` to a label address resolved at assemble time. The optimizer may rewrite jumps but must keep targets on instruction boundaries (`verify_bytecode` enforces this).

### Tracing
`pegassus trace prog.ir` prints each op with optional source line mapping stored in `codeline` during assembly. This is the primary debugging tool when results look wrong.

### Gas / steps
`max_steps` stops infinite loops. Override with `--steps N`.

### Relationship to Altair
The VM is Altair source. Fast paths (for example keeping L0–L7 in named numerics) are implementation details; the IR model remains “all locals are indices into a 1 MiB buffer”.

## Español

### Panorama
Pegassus ejecuta un array lineal de bytecode. Cada instrucción es un opcode con operandos inmediatos opcionales (slots, saltos, ids de string).

Hay tres regiones importantes:

1. **Pila de operandos** — casi todos los cálculos.
2. **Locales** — celdas de acceso aleatorio por índice.
3. **Pila de llamadas** — direcciones de retorno de `call` / `ret`.

Además: **pool de strings**, handles de archivo opcionales y arrays opcionales.

### ¿Por qué máquina de pila?
Facilita emitir código sin asignar registros. `(a+b)*c` es:

```text
load 0
load 1
add
load 2
mul
```

### Puntero de instrucción
`ip` avanza. Los saltos asignan `ip` a una label resuelta al ensamblar. El optimizador puede reescribir saltos pero los destinos deben caer en límites de instrucción (`verify_bytecode`).

### Trace
`pegassus trace prog.ir` muestra cada op y la línea fuente si existe. Herramienta principal de depuración.

### Gas / pasos
`max_steps` corta bucles infinitos. `--steps N` lo cambia.

### Relación con Altair
La VM está en Altair. Acelerar L0–L7 es detalle de implementación; el modelo IR sigue siendo índices sobre un buffer de 1 MiB.
